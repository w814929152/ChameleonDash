# ChameleonDash — 项目长期笔记

## 是什么
Godot 4.7 双色切换跑酷。三层横版跑道，每层一条道，**大部分段只有 1-2 层有跑道**
（大幅留空）。同色攒能量、异色吃能量、能量归零即死；切色清空能量；
冲刺 24 m/s 耗 24/s。

**跳跃（key: W/S 或 上/下）**：落点 = 该方向最近的实体跑道；空层自动跳过、
不穿透实体；按【次】计费 8 点（跨几层都是 8）。**该方向没有跑道 → 原地跳**
（不换层、不前进），按键永远有反馈；原地跳在**同色轨道免费、异色轨道照收 8 点**。
落地冷却为 0（落地当帧即可再跳）。空中不能跳。

**跳跃弧线（2026-10-10 整合，**这条是新设计**）**：「跳跃」和「跳到上一层」不再是
两套公式 —— 顶点由 `JUMP_APEX_Y` **固定为绝对高度 = 顶层 + 1.2 = 7.6m**，
向上跳/原地跳/跨空层跳两层**共用同一条抛物线**，只是系数不同：
`y = 层A + b·t + a·t²`，过两端点且峰值恰为 `JUMP_APEX_Y`
（`b = 2u√m, a = d − b, u = √m + √(m−d)`，`m = 顶点−层A`，`d = 层B−层A`）。
峰值时刻自动分叉：原地跳 0.5 / 跳一层 ≈0.568 / 跳两层 ≈0.716。
**落点仍由方向上的最近实体跑道决定** —— 顶点统一 ≠ 落点统一。
守卫 `LogicTest._test_unified_jump_arc`（三种跳跃峰值都 = 7.6）。
⚠ 用户明确接受的两个代价：① 从第 1 层跳会冲到顶层之上再落回中层，跳一层与跳两层
【视觉一样】；② 层越低这一跳越夸张。弧线**不再透露落点**，靠光环 + HUD 补。

**别再引入第二套跳线曲线**：旧的 `INPLACE_JUMP_ARC = 3.53678` 是"调参把两套曲线凑成
一样高"的产物，已删除。凑出来的相等会在下一次调参时无声失效 —— 那是同一个坑。

**跳跃射程**：滞空 `JUMP_AIR_TIME = 0.58s`（原 0.5）→ 一次跳跃前进 12×0.58 = **6.96m**。
**上限由三档成本卡死**：每跳固定 8 点，单价 = 8/(12×0.58) = 1.15 点/米；
到 0.67s 就跌破冲刺的 1.0，"冲刺最便宜"作废。**想再加长必须同步抬高
`JUMP_ENERGY_COST`，不能只动这一个数。**

**下落**：不换层只换 _y 的位移现在都是**动画**，没有瞬移。
节奏 = `FALL_AIR_TIME = 0.5s`（**已与跳跃解耦**，重力本来就该更快；且坠落落点
已经验证过，不该被"改跳跃手感"顺带改掉），曲线走 **t²**（从静止加速）。
踩空（`_check_track_gap`）不再一帧改 layer+_y，而是起一段 `falling` 空中状态
（能量冻结、不可再跳、落地压扁更狠 0.60），**落地才换层**。HUD 文案区分「空中/坠落」。

**下落的"表现"= 轨迹 + 剪影，两样都要**（缺一样就只剩"位置在变"）：
- 剪影：`FALL_STRETCH = 1.38`，纵向拉伸**随 t 线性**（t² 的瞬时速度 ∝ t，常量拉伸
  与"起坠速度≈0"矛盾），体积守恒 → 横向收窄到 0.85。与起跳拉伸 1.32 刻意错开，
  上跳/坠落两种剪影必须不同 - 否则玩家分不清"我在跳"还是"我在掉"。
- 参照物：**向下运动时光环贴【落点层】，上跳保持留【出发层】**。
  被留下的东西必须在玩家身后 —— 上跳时出发层在下方（自然），坠落时出发层在**头顶**
  （悬空铁圈，最像 bug 的东西）。且坠落期间玩家无法操作，唯一有意义的判断就是
  "我落下去的那层是不是我的颜色"，光环就该待在那个位置。

**三档穿异色成本（设计意图，不是巧合）**：硬闯 1.5 ＞ 连跳 ~1.25 ＞ 冲刺 1.0 点/米。
（滞空 0.5→0.58 之后，连跳这一档从 1.38 压到 ~1.25，实测值见 SelfTest 的"冲刺门"行。
“连跳"永远是【下界】：它要求每一跳都落地即按，真人不成立。）

## 工作约定（重要）
- **数值唯一真理来源 = `scripts/GameConfig.gd`**。任何 magic number 必须住在这里，
  且每条必须带 rationale（为什么是这个数）。改数值只改这个文件。
- **关卡数据唯一来源 = `scripts/LevelData.gd`** 的 `level_1/2/3()`，纯数据驱动，
  不改场景文件。segment 格式：`{length, colors:[下层,中层,上层], 可选: boost/pulse/crystals}`。
- 颜色字面量：`A=0` 青 / `B=1` 橙 / `X=-1` 缺口。
- 三条（现四条）关卡硬约束：可通关性、多解性、可读性（段长 ≥ 12m）、
  **不依赖晶体**（可通关性不得依赖任何拾取物）。
- 多解的判定标准：**四种原型（冲刺/保守/切色/连跳）里至少三型能通**。
  两型能通仍然像在背答案。
- **留空纪律 A：门必须建在玩家已经站着的层上。** 冲刺要满能量，而跳跃扣 8 点，
  所以"跳一下才够得着"的门永远不可能被冲刺通过。
- **留空纪律 B：脉冲段必须有两层。** 单层上无处可跳 → 唯一的应对手段失效。
- 空缺的用法（关卡设计词汇表，详表见当日日志）：独木桥 / 逼迁 / 收费口 / 断头台。

## 会骗人的东西（都真踩过）
- **`%.2f` 会把 `0.9999999` 打成 `1.00`**。看到「`arc_t=1.00` 但 `空中=true`」时别急着
  判定状态机坏了 —— 先想清楚打印精度。`jump_t` 是浮点累加，会差一帧到不了 1.0。
- **GDScript `var x := a if c else b` 会 Parse Error**（Cannot infer the type），
  必须显式 `var x: float = ...`。而且**失败时场景静默不加载、什么都不打印**。
  改完脚本先跑 `--check-only --script res://scripts/Xxx.gd`。
  ⚠ 但 `--check-only` 对 `class_name` 全局类一律假报 `Identifier not found`（连没动过的
  文件也报）—— 它只能抓"语法/类型推断"错，不能当编译通过的证据。
- **`set_process(false)` 必须在 `add_child` 之后调**。Godot 在节点进树时会按"脚本里
  有没有 `_process`"重新打开处理开关，之前关的会被覆盖。症状极隐蔽：整段同步循环
  （不跨帧）时根本看不出来，一旦 `await` 跨帧就变成"重开一局后距离不是 0 而是 0.8m"。
- **`%.0f` 会把 99.7 打成 100**。我据"报告里写着满能量"写了 `energy >= ENERGY_MAX`
  的判据，而它永远是假 —— 结果是"冲刺一次都没发生"。**判"能不能做到"要问引擎
  （`_dash_armed`），不要手算。**

## 铁律：校验器不许复刻引擎物理
2026-10-10 事故：校验器三关全绿，实机却"跳跃按键无效"——
因为校验器按「段边界」解析跳跃落点，引擎按「当前距离」解析，两套规则不同。
**凡是要验"物理能不能做到"，一律调用引擎本体（如 `Player.next_track_layer`），
绝不在校验器里重写一遍。复刻 = 制造假阳性；校验通过而玩不了，比没有校验更危险。**

**反向也要防（2026-10-10 夜）**：弱 bot 会造假阴性 —— 关卡其实能过、bot 过不去。
所以 PlayTest 的断言失败时，**先怀疑 bot 的能力，再怀疑关卡**。
PlayTest 自己踩到过两个这种坑：① 只往上看逃生口（站顶层时"上"不存在）；
② 用"本层连续同色长度"当"必须硬扛的长度"，把 L3 段4 那道 68m 的门读成 98m
（段5 的层2 是同色，是逃生口，不该算进去）→ 于是判成"冲不过"改走切色，
报告里再也看不到冲刺门。**判"值不值得跳"要用连续长度，判"冲刺够不够"要用
扣掉逃生口的那一段，两者混用会同时错两件事。**


**冲刺 = 模式，不是动作**（`Player._update_dash_arming`）：能量到过 `ENERGY_MAX` 才
arm；按住不放才持续；一松手 `_dash_armed` 就清零，**必须重新攒满才能再冲**。
所以"来不及了再冲刺"永远按不出来 —— 这是留空纪律 A 的另一面。
建模时**绝不能每帧重算"满能量"**（冲刺第一帧能量就掉到 100 以下）→ 判据要分
「起冲 / 保持」两段。冲刺期间 `能量 − 剩余米数` 是常量（1.0 点/米 掉、1.0 米/帧 走），
起冲时证明过的事冲完之前一直成立。

## 未决（已量化，等用户拍板，别自己改关卡）
- **L2/L3 的星级线偏松**。SelfTest 的"理论最优"（L2 52.98 / L3 55.37）比 PlayTest
  实机（49.2 / 52.5）慢 5~7%，因为**纸面把脉冲段按"整段时间都站在异色上"估最坏情况**，
  而实机玩家（和 bot）会跟着相位换层，根本不挨那份打。星级线是从纸面最优派生的，
  于是实际倍率从设计的 ×1.04 变成 ≈×1.18。L1 没脉冲，两边只差 0.28s —— 佐证了病因。
- **L3 段11「补满段」短了约 5~9m**。它按"脉冲后残血 35 点"设计成 100m；但校验器
  自己算出的最坏残血是 **27.6 点**，要 109m 才能把冲刺重新 arm 起来。于是在纸面
  最坏情况下，段12 的 85m 冲刺门打不开（SelfTest 冲刺流在那里被迫转了切色）。
  实机没事（bot 段11 入场就 68 点，100m 后满）。**要不要加长到 110m 由用户定 —— 
  改长度会连带改二/三星线。**
- **"冲刺门"目前不是硬门**：整段单色且 ≤100m 时，切色也能过（切色只清能量、清完
  立刻在同色段回血，残余能量反而比冲刺多）。冲刺真正赢的是**速度** —— 所以它在
  三关里都是"三星的唯一解"而非"通关的唯一解"（不用冲刺的三次跑动分别超三星线
  1.1 / 0.7 / 0.9 秒）。只有 >100m 的整段单色才是真正"只能切色"（L3 段6）。

## 设计支柱
**风险必须可读**。任何让"我脚下是不是我的颜色"这个判断变慢的东西都是 bug。
由此派生：跑道不透明不混色、玩家永远是画面最亮、亮度是手段色相是目的、
背景物绝不允许出现在玩家会做判定的视觉走廊上。

## 已知可调旋钮（带判据）
- `DEATH_GRACE_SEC` 0→0.4：若"手滑误切致死"占比 > 30%
- `FALL_ENERGY_COST` 8→致死：若单次通关坠落 > 3 次
- `PULSE_PERIOD` 1.6s：可读性下界 1.2s、紧张感上界 2.4s
- `FALL_STRETCH` 1.38：**纯表现层，不进任何成本/可通关性计算**。
  下界 = 要和起跳拉伸 1.32 拉开差别（否则分不清在跳还是在掉）；
  上界 = 横向 1/√s 不能细成一根针（s=1.5 时横向 0.82）。
- `JUMP_APEX_CLEARANCE` 1.2：**顶点 = 顶层 + 本值**。
  下界 = 顶层原地跳要肉眼可见（角色高 1.4m，抬 1.2m 才算离地）；
  上界 = **实测**顶点角色的顶部世界 y≈9.63，HUD 底边≈9.70，只剩 3px。
  想再抬高必须先改相机纵向锚点或 HUD 布局。
- `JUMP_AIR_TIME` 0.58：上界由三档成本卡死（见上，0.67s 是临界点）。
