# ChameleonDash — 项目长期笔记

## 是什么
Godot 4.7 双色切换跑酷。三层横版跑道，每层一条道，**大部分段只有 1-2 层有跑道**
（大幅留空）。同色攒能量、异色吃能量、能量归零即死；切色清空能量；
冲刺 24 m/s 耗 24/s。

**跳跃（key: W/空格 = 跳，S = 落）· 2026-10-10 三次定稿：只有单纯的跳跃**
**全局只有一条竖直规则：【一次动作有一个峰值高度；落点 = 峰值之下最高的实体跑道】。**
跳跃**不指定目标层** —— 它只决定"我能升多高"，层是升上去自己撞到的。
- `跳跃`：峰值 = 出发层 + `JUMP_APEX_HEIGHT`(4.4 = 层间距 3.2 + 余量 1.2)，
  受 `JUMP_APEX_MAX_Y`(7.6) 夹住 → 顶层起跳只有 1.2 小弹跳（**全关唯一例外**，三层盒子的顶盖）
- `S 落` / 踩空：峰值 = 出发层（不上升），可一次掉过多层
- 跳跃 / 下坠 / 踩空**三条路径共用 `Player._resolve_landing(lowest, highest, time_for: Callable)`**。
  旧版这里有【两份】落点代码，别再分家 —— 分家正是"跳跃按键无效"事故的根因。
- 按【次】计费 8 点；**弹回本层**才看颜色（同色免费 / 异色照收 8 点）。
  没换层就没位移，按键永远有反馈、绝不致死。

**"只能跳一层"是几何推论，不是规则**：4.4 够到 +3.2，够不到 +6.4。
想让跳跃跨两层，必须把峰值抬到 6.4 以上 —— 那正是用户说的"过高"。
⚠ 反过来：**任何"N → N+2"的段间衔接都走不通了**。
`SelfTest.check_forward_escape`（直接调引擎）专门抓这个，历史上抓到过 L2 段10。
向下不受限：坠落依然是"落到下面最高的那条"。

**曲线**：抛物线 `y = 出发层 + b·t + a·t²`（`b = 2u√m, a = d − b, u = √m + √(m−d)`，
`m = 峰值−出发层`，`d = 落点层−出发层`）。现在只可能三种形状：
d = 0 弹回本层（对称，t_p = 0.5）/ d = +3.2 跳上一层（t_p ≈ 0.657）/ d 为负（段末尾起跳落到下面）。
分支按 `falling` 判，**不要**再用 `jump_to < jump_from`（跳跃也可能落到更低的层）。
守卫 `LogicTest._test_unified_jump_arc`。
（历史：顶点曾被钉成绝对 7.6m，再改成"落点+余量 1.2"，用户两次反馈后定稿成本版。
顶点现在**只由出发层决定** → 弧高不再透露落点，"我会落在哪"交给光环 + HUD 层号。）

**别再引入第二套跳线曲线**：旧的 `INPLACE_JUMP_ARC = 3.53678` 是"调参把两套曲线凑成
一样高"的产物，已删除。凑出来的相等会在下一次调参时无声失效 —— 那是同一个坑。

**顶点只进视觉，不进判定**：`_y` 只被 `_update_transform`（位置/光环/挤压）读，
落点由 `_resolve_landing` 一次算定。所以**改峰值不会让 SelfTest/PlayTest 的
任何数字变化** —— 那两套校验全绿只证明"没改坏"，**证明不了跳高好看**，
后者只能靠截图（`shots/jump*.png` + 打印里的 `y=`）。

**跳跃射程**：滞空 `JUMP_AIR_TIME = 0.58s`（原 0.5）→ 一次跳跃前进 12×0.58 = **6.96m**。
**上限由三档成本卡死**：每跳固定 8 点，单价 = 8/(12×0.58) = 1.15 点/米；
到 0.67s 就跌破冲刺的 1.0，"冲刺最便宜"作废。**想再加长必须同步抬高
`JUMP_ENERGY_COST`，不能只动这一个数。**

**下落（2026-10-10 四次定稿）= 自由落体，时长不是常量**。
【一次动作有一个峰值高度；落点 = 峰值之下最高的实体跑道】这条规则对下坠同样成立，
而且下坠**连时长都是算出来的**：`t = √(2·落差/g)`。
- `FALL_ONE_LAYER_SEC = 0.5` 是唯一的自由参数（标定锚点，"掉一层半秒"，沿用旧手感
  → 最常见那次坠落逐帧不变）；`FALL_GRAVITY = 2·LAYER_SPACING/0.5² = 25.6 m/s²`。
  **掉一层 0.50s（6.0m）／掉两层 0.71s（8.49m）** —— 落差越大掉得越久。
- 曲线**一个字都没改**（仍是 `lerp(出发层, 落点层, t²)`）：t² 配上 `_air_time = √(2h/g)`
  展开就**恒等于** `出发层 − ½g·τ²`。变的只是 `_air_time` 从常量变成重力解。
- `_resolve_landing` 的签名因此从 `land_time: float` 改成 **`time_for: Callable`
  （"落到第 l 层要几秒"）** —— 这是跳跃/下坠唯一的分家处，且是**显式传进来的**：
  跳跃传 `_jump_time_to`（常量）、下坠传 `_fall_time_to`（重力解，随落差生长）。
  一套循环、一套 `color_at` 判定、一套"从高往低取第一块"，都不许再分。
- 踩空（`_check_track_gap`）同源：起一段 `falling` 空中状态（能量冻结、不可再跳、
  落地压扁更狠 0.60），**落地才换层**。HUD 文案区分「空中/坠落」。
- ⚠ **旧的 `FALL_AIR_TIME = 0.5` 常量已删**。它两个错：观感错（掉两层和掉一层一样快）
  与结构错（一个纯物理量被玩法旋钮钉住）。任何地方要用下坠时长，一律调
  `GameConfig.fall_air_time(出发层, 落点层)`，**不许本地重算 √(2h/g)**。

**"这次动作会前进多远"必须分方向**（`Player.reach_to(落点层)`，已取代 `jump_reach()`）：
上跳/原地弹 = `_cur_speed × JUMP_AIR_TIME`（6.96m）；下坠 = `_cur_speed × fall_air_time`
（掉一层 6.00m、掉两层 8.49m）。**一个数糊两个方向两边都会错** ——
拿 6.96 判"掉一层来得及"会提前 0.96m 喊"现在可以按"，按下去落点仍在缺口里
（"按键无效"的老症状）。HUD 的「现在！」窗口与 PlayTest 的 bot 决策都读它。

**下落的"表现"= 轨迹 + 剪影，两样都要**（缺一样就只剩"位置在变"）：
- 剪影：`FALL_STRETCH = 1.38`，纵向拉伸**随 t 线性**（t² 的瞬时速度 ∝ t，常量拉伸
  与"起坠速度≈0"矛盾），体积守恒 → 横向收窄到 0.85。与起跳拉伸 1.32 刻意错开，
  上跳/坠落两种剪影必须不同 - 否则玩家分不清"我在跳"还是"我在掉"。
- 参照物：**向下运动时光环贴【落点层】，上跳保持留【出发层】**。
  被留下的东西必须在玩家身后 —— 上跳时出发层在下方（自然），坠落时出发层在**头顶**
  （悬空铁圈，最像 bug 的东西）。且坠落期间玩家无法操作，唯一有意义的判断就是
  "我落下去的那层是不是我的颜色"，光环就该待在那个位置。

**三档穿异色成本（设计意图，不是巧合）**：硬闯 1.5 ＞ 连跳 ~1.25 ＞ 冲刺 1.0 点/米。
（滞空 0.5→0.58 之后，连跳这一档从 1.38 压到 ~1.25，实测值见 SelfTest 的"冲刺门"行。
“连跳"永远是【下界】：它要求每一跳都落地即按，真人不成立。）

## 工作约定（重要）
- **数值唯一真理来源 = `scripts/GameConfig.gd`**。任何 magic number 必须住在这里，
  且每条必须带 rationale（为什么是这个数）。改数值只改这个文件。
- **关卡数据唯一来源 = `scripts/LevelData.gd`** 的 `level_1/2/3()`，纯数据驱动，
  不改场景文件。segment 格式：`{length, colors:[下层,中层,上层], 可选: boost/pulse/crystals}`。
- 颜色字面量：`A=0` 青 / `B=1` 橙 / `X=-1` 缺口。
- **五条**关卡硬约束：可通关性 / 多解性 / 可读性（段长 ≥ **17.0m** = `SPEED_DASH
  × fall_air_time(2→0)`；下坠改自由落体后从 13.9 抬上来）/ **不依赖晶体** /
  **竖直可达性（禁止跨两层衔接，`check_forward_escape` 抓）**。
- segment 格式：`{length, colors:[下层,中层,上层], 可选: boost/pulse/crystals/toll}`。
- 多解的判定标准：**四种原型（冲刺/保守/切色/连跳）里至少三型能通**。
  两型能通仍然像在背答案。
- **留空纪律 A：门必须建在玩家已经站着的层上。** 冲刺要满能量，而跳跃扣 8 点，
  所以"跳一下才够得着"的门永远不可能被冲刺通过。
- **留空纪律 B：脉冲段必须有两层。** 单层上无处可跳 → 唯一的应对手段失效。
- **留空纪律 C：冲刺门前必须有足够长的同色补满段**，长度 = 1.5 × (100 − 进门能量) m。
  A 只是必要条件，能量还得真的到**满**。漏了这条 → 冲刺流反而比保守流慢：
  L2 段6 曾只 42m，冲刺流差 2 点到满、被逼切色，慢 6.4 秒
  ——"一条名叫冲刺门的门，最想冲刺的那型玩家却冲不了"。
- **纪律 D：收尾段必须对两种颜色都友好**，否则整关被一条支线否掉
  （L2 曾有"名叫缓冲的段却在最后 54m 继续收费"，橙玩家会死在终点线前）。
- **`toll: true` = 收费口标记**（把作者意图写进数据）：收费口 `[A,-1,A]` 与"软门"
  **地形完全相同**（纯异色短段），校验器没法从地形区分，会误报"冲刺失去意义"。
  标了 toll 就跳过它。⚠ 别只把 `not toll` 加到软门那条 if 上 —— 它会掉进 elif 链、
  被当成"冲刺门"记进 `gate_notes`，误报只是换个地方接着撒。要单开一个 `if toll: pass`。
- 空缺的用法（词汇表 v3，9 种地形，详表见 `LevelData` 头部）：独木桥 / 上跳梯 /
  自由落体 / 双层站 / 逼迁 / 收费口 / 分层解法 / 断头台 / 加速带。

## 会骗人的东西（都真踩过）
- **`%.2f` 会把 `0.9999999` 打成 `1.00`**。看到「`arc_t=1.00` 但 `空中=true`」时别急着
  判定状态机坏了 —— 先想清楚打印精度。`jump_t` 是浮点累加，会差一帧到不了 1.0。
- **GDScript `var x := a if c else b` 会 Parse Error**（Cannot infer the type），
  必须显式 `var x: float = ...`。而且**失败时场景静默不加载、什么都不打印**。
  改完脚本先跑 `--check-only --script res://scripts/Xxx.gd`。
  ⚠ 但 `--check-only` 对 `class_name` 全局类一律假报 `Identifier not found`（连没动过的
  文件也报）—— 它只能抓"语法/类型推断"错，不能当编译通过的证据。
- **`set_process(false)` 必须在 `add_child` 之后调**。Godot 在节点进树时会按"脚本里
  有没有 `_process`"重新打开处理开关，之前关的会被覆盖。症状极隐蔽：整段同步循环
  （不跨帧）时根本看不出来，一旦 `await` 跨帧就变成"重开一局后距离不是 0 而是 0.8m"。
- **`%.0f` 会把 99.7 打成 100**。我据"报告里写着满能量"写了 `energy >= ENERGY_MAX`
  的判据，而它永远是假 —— 结果是"冲刺一次都没发生"。**判"能不能做到"要问引擎
  （`_dash_armed`），不要手算。**

## 铁律：校验器不许复刻引擎物理
2026-10-10 事故：校验器三关全绿，实机却"跳跃按键无效"——
因为校验器按「段边界」解析跳跃落点，引擎按「当前距离」解析，两套规则不同。
**凡是要验"物理能不能做到"，一律调用引擎本体（如 `Player.next_track_layer`），
绝不在校验器里重写一遍。复刻 = 制造假阳性；校验通过而玩不了，比没有校验更危险。**

**反向也要防（2026-10-10 夜）**：弱 bot 会造假阴性 —— 关卡其实能过、bot 过不去。
所以 PlayTest 的断言失败时，**先怀疑 bot 的能力，再怀疑关卡**。
PlayTest 自己踩到过两个这种坑：① 只往上看逃生口（站顶层时"上"不存在）；
② 用"本层连续同色长度"当"必须硬扛的长度"，把 L3 段4 那道 68m 的门读成 98m
（段5 的层2 是同色，是逃生口，不该算进去）→ 于是判成"冲不过"改走切色，
报告里再也看不到冲刺门。**判"值不值得跳"要用连续长度，判"冲刺够不够"要用
扣掉逃生口的那一段，两者混用会同时错两件事。**


**冲刺 = 模式，不是动作**（`Player._update_dash_arming`）：能量到过 `ENERGY_MAX` 才
arm；按住不放才持续；一松手 `_dash_armed` 就清零，**必须重新攒满才能再冲**。
所以"来不及了再冲刺"永远按不出来 —— 这是留空纪律 A 的另一面。
建模时**绝不能每帧重算"满能量"**（冲刺第一帧能量就掉到 100 以下）→ 判据要分
「起冲 / 保持」两段。冲刺期间 `能量 − 剩余米数` 是常量（1.0 点/米 掉、1.0 米/帧 走），
起冲时证明过的事冲完之前一直成立。

## 已决（2026-10-10 第五次定稿：按新机制重排三关）
三关全长 L1 617m / L2 726m / L3 722m。用户原话「按照修改后的机制，重新设计关卡」。
- **星级线重标**：L2 59/55 → **58/54**、L3 63/58 → **60/56**（L1 53/49 不变）。
  旧线偏松的病因（纸面把脉冲段按"整段都站在异色上"估最坏）已随重排消失 ——
  现在纸面最优与实机最优差 **<0.7%**，实际倍率回到设计的 ×1.12 / ×1.04。
  实机验证：**"不用冲刺"被挡在二星外**（L2 58.1>58、L3 60.2>60），"全能"余 6~7s。
- **L3 段11 补满段 100 → 115m**（校验器算出的最坏残血是 27.6 点，需 109m）。
- **L2 段6 42→52m、段8 80→90m**（冲刺门冲不起来的修复，见纪律 C）。
- **L2 段10/段11 跨两层死局已修**（拆成 +1 两连：先双层青缓冲，再 +1 上跳）。
- 顺带：`PlayTest` 星级断言改为**从 `main.level.target_time` 读**（原本硬编码 L1 的
  53.1/53.0/49.0 —— 抄副本会让调线后的断言静默失效，同"不许复刻"纪律）。

## 仍未决
- **"冲刺门"不是硬门**：整段单色且 ≤100m 时，切色也能过（切色只清能量、清完
  立刻在同色段回血，残余能量反而比冲刺多）。冲刺真正赢的是**速度** —— 所以它在
  三关里都是"三星的唯一解"而非"通关的唯一解"。只有 >100m 的整段单色才是真正
  "只能切色"（L3 段6）。这是设计取舍，不是缺陷。

## 设计支柱
**风险必须可读**。任何让"我脚下是不是我的颜色"这个判断变慢的东西都是 bug。
由此派生：跑道不透明不混色、玩家永远是画面最亮、亮度是手段色相是目的、
背景物绝不允许出现在玩家会做判定的视觉走廊上。

## 已知可调旋钮（带判据）
- `DEATH_GRACE_SEC` 0→0.4：若"手滑误切致死"占比 > 30%
- `FALL_ENERGY_COST` 8→致死：若单次通关坠落 > 3 次
- `PULSE_PERIOD` 1.6s：可读性下界 1.2s、紧张感上界 2.4s
- `FALL_STRETCH` 1.38：**纯表现层，不进任何成本/可通关性计算**。
  下界 = 要和起跳拉伸 1.32 拉开差别（否则分不清在跳还是在掉）；
  上界 = 横向 1/√s 不能细成一根针（s=1.5 时横向 0.82）。
- `JUMP_APEX_HEIGHT` 4.4（= `LAYER_SPACING` 3.2 + `JUMP_APEX_CLEARANCE` 1.2）：
  **顶点 = `jump_apex_from(出发层)` = `出发层 + 4.4`，被 `JUMP_APEX_MAX_Y`(7.6) 夹顶**。
  这是"跳跃够到几层"的唯一旋钮 —— 抬到 6.4 以上才会解锁"一次跳两层"，
  压到 3.2 以下就连一层都跳不上（落点还是由峰值下最高的实体跑道决定，几何自动跟随）。
  上界 = 顶层起跳被夹成 7.6，**实测**角色顶部世界 y≈9.63、HUD 底边≈9.70，只剩 3px；
  想再抬高必须先改相机纵向锚点或 HUD 布局。
- `JUMP_APEX_CLEARANCE` 1.2（余量，顶点高出落点层多少）：下界 = 原地跳要肉眼可见
  （角色高 1.4m，抬 1.2m 才算离地）；**这是"跳上去刚好够到上一层"的那点冗余**，
  压到 0 就变成"贴脸擦过去"，卡不住手感。
- `JUMP_AIR_TIME` 0.58：上界由三档成本卡死（见上，0.67s 是临界点）。
- `FALL_ONE_LAYER_SEC` 0.5：**下坠唯一的旋钮**（g 由它派生，别去直接改 `FALL_GRAVITY`）。
  它同时决定"掉多久"和"缺口里飞多远"（掉一层 6.0m / 掉两层 8.49m），
  所以改完必须重跑三套校验。0.4 更利落但 8 点的惩罚感变弱；0.7 更沉但拖慢关卡节拍。
  下界判据 = HUD 的「现在！按 S」窗口要留得住（< ≈0.35s 玩家读不到那个瞬间）；
  上界 = 掉两层的 0.71s 不能长到"我明明能操作却动不了"（> ≈0.9s 会烦）。
